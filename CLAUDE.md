# Fathom Site

Public marketing site for fathom (fathomvision.app): visual assistance for blind and low-vision iPhone users. Pages: landing, support, feedback, privacy, terms, accessibility, release notes, promo.

## Stack

- Next.js 16 App Router, React 19, TypeScript strict
- Tailwind CSS v4, CSS-first — no `tailwind.config`; the theme lives in `app/globals.css` via `@theme inline`
- Dark theme is the default; light via `[data-theme]` (`components/ThemeProvider.tsx`)
- Forms: Resend via Route Handlers. Analytics: PostHog. Tests: Vitest + Testing Library + jest-axe. Deploys: Vercel, `main` auto-deploys.
- Typed content data in `lib/` (`faq.tsx`, `releases.ts`, `landing-content.ts`, `app-facts.ts`); components in `components/`

## Design Governance

### Design authority

These documents and token files win over your defaults. Read the design system doc before any UI work. They are referenced by path on purpose — read them when doing UI work, don't inline them.

| What | Where |
|---|---|
| Design system | The app's design system is the source of truth: artifact https://claude.ai/artifact/62m3pWCm3uSiyouXi5WkXA, mirrored in project-homer `docs/design-system/`. The site vendors `tokens.json` and the logo SVGs into `design-system/vendor/` (pinned in `design-system/SOURCE.json`) |
| Site spec + decision log | `docs/superpowers/specs/2026-09-25-site-1.3-revamp-design.md` (supersedes the homepage sections of the 05-30 and 09-05 specs; the 05-30 AAA acceptance criteria still apply) |
| Tokens (code) | `design-system/generated/*.css` (generated by `npm run ds:build`, never hand-edited) + `app/globals.css` (`@theme inline` bridge, a11y blocks) + `app/site-tokens.css` (site-only scale) |
| Components | `components/` (Button, Surface, Section, Header, Footer, Faq, ContactForm…), `components/phone/` (app screen mockups), `components/brand/` (mark, lockup) |
| App facts | `lib/app-facts.ts`: every app string, pinned to the app reference build (`scripts/check-app-facts.mjs`) |
| Accessibility | AAA criteria in the 05-30 spec: primary text ≥ 11.2:1, targets ≥ 44px |

Every color, spacing, radius, type and motion value comes from the app's `tokens.json` (the app generates `FathomTokens.swift` from the same file). Never change a vendored or generated token in this repo: change it in the design system, then `npm run ds:sync`. Site-only values (the AAA role layer `--site-*`, the marketing display scale) live in `design-system/extensions/` and `app/site-tokens.css`, and every one is logged back to the design system.

### Audit before build

Never implement UI from scratch. First:
1. Search existing components, tokens, patterns, and terminology for anything similar.
2. Report what exists and what you'll reuse — before writing code.
3. Propose a new pattern only when nothing existing satisfies the requirement, and say why. The design spec's YAGNI list is binding — features it excludes stay excluded.

### Token rules

Every visual value comes from a token. No raw hex/rgb, no magic spacing, radii, font sizes, shadows, or durations.

| Value | Source |
|---|---|
| Colors | Tailwind utilities generated from `@theme inline` (`bg-bg`, `text-accent`…) or the CSS vars in `app/globals.css` |
| Arbitrary values | Banned in new code: no `text-[#…]`, `p-[13px]`, `rounded-[7px]`, `text-[var(--…)]`. Older code still has some `-[var(--…)]` utilities; replace them when you touch the file |
| Type | Atkinson Hyperlegible Next (all text) and Atkinson Hyperlegible Mono (distances, counters) via `next/font/google`, served from this domain; sizes from the DS type styles |
| Radii / spacing / easing / section rhythm | DS `--fathom-radius-*`, `--fathom-space-*`, motion tokens; site rhythm in `app/site-tokens.css` |
| Themes | Dark (default) and light via `[data-theme]`; `prefers-contrast: more` maps to the DS Contrast Boost values automatically. Every new color needs a dark and a light value |

### State matrix

Before coding a new screen or flow, list one line per state: loading, empty, error, permission denied, long content, reduced motion, VoiceOver/keyboard, success, recovery after failure. Present the matrix, then implement. A feature without its failure states isn't done.

### Accessibility floor

Non-negotiable in every project:
- No pure #000 or #FFF — warm ink only. Pure values cause halation for low-vision users.
- Color never carries meaning alone. Pair it with borders, position, or text.
- Focus states are designed with the component, not added after.
- Touch/click targets ≥ 44px.
- Contrast checked at design time against actual token values. WCAG AA is the floor.
- Reduced motion honored — every animation has a no-motion path.

This site targets AAA (≥ 11.2:1 primary text) — its audience is the app's audience. Every new component gets a jest-axe test. Never override the a11y blocks in `globals.css` (`prefers-contrast`, `:focus-visible`, reduced-motion, skip link).

### Design-system changes

New tokens, variants, or components get reported separately from feature work, with the reason existing ones can't serve. Never silently extend the system for one feature.

### Copy and claims

- fathom is always lowercase, including at the start of a sentence; the tier is "fathom plus". Exceptions: "Fathom: Visual Assistance" (App Store name, JSON-LD name), Apple's own labels ("choose Fathom" in iOS Subscriptions), "Unruly Vision, LLC".
- American English, distances in feet, sentence case, curly quotes and apostrophes, no em dashes, no emoji.
- Never claim fathom sees, verifies or guarantees something it can't. Go asks whether you've arrived. "Always on" is only for obstacle alerts. Never "nothing leaves your phone".
- Every string inside a phone mockup is an app string from `lib/app-facts.ts` or an illustrative example from `EXAMPLES`. `test/helpers/copy-rules.ts` enforces the rules on every marketing surface.
- The privacy page, Terms and the FAQ privacy answer are legal text: restyle, never reword, unless Ryan asks. Their evidence lives in the private app repo (`docs/privacy/SITE-PRIVACY-SOURCES.md`).

### Review

After UI work, run `product-design-reviewer` and `accessibility-reviewer` (in `.claude/agents/`). The builder never self-certifies design or accessibility.
